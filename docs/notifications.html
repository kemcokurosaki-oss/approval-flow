① リマインダー通知（催促）

対象: scripts/notify-reminders.js　実行: GitHub Actions .github/workflows/notify-reminders.yml（本来は毎日9:00 JST自動実行想定だが、現状cronはコメントアウトで無効化・手動実行のみ）

#種類対象フロー送るタイミング・頻度宛先（TO）CC
1 承認催促 機械組立・試運転・工場出荷
出荷準備は承認不要のため対象外		 申請の翌日以降、未承認（submitted）のままなら毎日 該当承認ステップの承認者ロールに該当する全員 承認者ロールが操業部長の場合のみ、操業（野津）を固定CC　画面から変更可
2 申請催促 機械組立・試運転・出荷準備・工場出荷 紐づくタスクの終了日を過ぎた翌日から毎日（工場出荷のみ予定日の前日から） 機械組立/試運転/出荷準備はタスク担当者（owner）、工場出荷は品証・製管スタッフ全員 機械組立→組立の課長・部長／試運転→操業の課長・部長／出荷準備・工場出荷→なし
3 案内催促 簡易検査・外観検査・出荷確認会議 基準タスク（簡易検査・外観検査は機械組立、出荷確認会議は自身）の終了/開始日の3日前から毎日（期日を過ぎても未送付なら継続） 品証・製管スタッフ全員 なし
4 ペンディング項目
期日超過催促		 全フロー共通
実質は簡易検査・外観検査・出荷確認会議のみ（出荷準備はペンディング項目を持たないため対象外）		 完了予定日（due）を過ぎた翌日から、完了にするまで毎日 ペンディング項目の担当者（owner） 品証（田中）・製管（森村・黒崎）を固定CC　画面から変更可
5 完了処理催促 簡易検査・外観検査・出荷確認会議 開催日（inspection_date）を過ぎた翌日から、「完了にする」処理をするまで毎日 品証（quality）ロール全員 製管（production_control）ロール全員
宛先は原則としてSupabaseの profiles テーブルのロール（role）に基づいて動的に決まる。 #1・#4のCCのみロールに紐づかない個人固定のため、アプリの設定画面（⚙️ → 通知・宛先設定 → リマインダー通知のCC設定）から変更できる。編集できるのは管理者（ADMIN_EMAILS）のみ。 送信タイミング（何日前/後から送るか）は現状コード直書きで、設定画面からは変更できない。 重複送信防止は approval_notifications テーブルで管理。

承認・却下

#通知種別notification_typeトリガー（操作）対象フロー宛先の決め方
1承認依頼approval_request 申請ボタン押下（初回申請）／並列承認でStep1が承認されStep2に進む時／出荷フローで品証が本申請（常務承認へ）する時／確定出荷日変更で再承認が必要な時 assembly・test_run・shipping 該当承認ステップの承認者ロールを持つprofiles全員
2再申請resubmit 却下された申請を修正し、再申請ボタンで送り直した時 承認ステップを持つフロー（assembly・test_run・shipping） 全承認ステップの承認者ロール（製管を除く）に紐づくprofiles
3完了通知completed 全承認完了時（並列承認のどちらかが承認、または直列の最終承認）／出荷準備は申請と同時（承認不要のため） assembly・test_run・shipping・shipping_prep フローごとの動的宛先（工番担当者・部署管理職）＋設定画面の固定宛先＋承認者本人
4他者承認完了（対応不要）completed_by_other 並列承認（assembly・test_run）で一方が承認し、他方の承認ステップが自動キャンセルされた時 assembly・test_run キャンセルされた側の承認者ロールに紐づくprofiles
5却下通知rejected 却下ボタン押下（コメント必須）時 承認ステップを持つ全フロー 申請者本人のみ

#通知種別notification_typeトリガー（操作）対象フロー宛先の決め方
11簡易検査 開催案内simple_inspection_invite 開催案内を送信した時 simple_inspection 動的宛先（組立/営業/設計担当者・管理職）＋設定画面の固定宛先
12外観検査 開催案内inspection_invite 開催案内を送信した時 inspection 動的宛先（組立/試運転/営業/設計担当者・管理職）＋設定画面の固定宛先
13出荷確認会議 開催案内shipping_meeting_invite 開催案内を送信した時 shipping_meeting 動的宛先＋固定宛先＋会場（ROOM_EMAILS固定マップ）の会議室メール
14簡易検査 日程変更simple_inspection_reschedule 日程変更を保存した時 simple_inspection その申請で既にメール送信済みの通知の宛先を再利用
15外観検査 日程変更inspection_reschedule 日程変更を保存した時 inspection 同上
16出荷確認会議 日程変更shipping_meeting_reschedule 日程変更を保存した時 shipping_meeting 同上
17簡易検査 キャンセルsimple_inspection_cancel キャンセル実行時 simple_inspection 既送信済み通知の宛先を再利用（未送信の招待自体は削除）
18外観検査 キャンセルinspection_cancel キャンセル実行時 inspection 同上
19出荷確認会議 キャンセルshipping_meeting_cancel キャンセル実行時 shipping_meeting 同上
20（汎用フォールバック）default app.js側での明示的な発生箇所なし — notify-approval.js側で未知のnotification_typeだった場合のみ使われる本文テンプレート
日程変更・キャンセル系（17〜22）は、招待メールを実際に受け取った人（emailed_atが入っている人）にだけ変更・キャンセルの通知が飛ぶ設計。
担当者変更や完了取消などの「訂正」操作時には、まだ送信されていない（emailed_atが空の）旧通知を取り消す仕組みがあり、誤送信を防いでいる。
現状、宛先は設定画面（⚙️ → 通知・宛先設定 → 通知の宛先設定）からフローごとに固定宛先・工番担当者の自動通知ON/OFFを編集可能。
